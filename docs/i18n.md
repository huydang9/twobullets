# UI language (i18n)

The client UI ships in **Vietnamese (default)** and **English**. Everything lives in `apps/client/src/i18n/`:

| File | What it holds |
|---|---|
| `vi.ts` | Vietnamese catalog. It defines the key list (`MessageKey`) and the `Messages` type. |
| `en.ts` | English catalog, typed `Messages`: a missing or extra key fails `pnpm typecheck`. |
| `core.ts` | `t(key, params?)`, `getLanguage()`, `setLanguage()`, `onLanguageChange()`. |
| `dom.ts` | `bindText()` / `bindTitle()` for static labels, `translateDom()`, `renderTemplate()` for templates with DOM nodes. |
| `format.ts` | `{name}` interpolation, plural selection (`Intl.PluralRules`), template splitting. |
| `language.ts` | `Language`, `resolveLanguage(search, stored)`. |

## How the language is chosen

1. `?lang=vi` or `?lang=en` in the URL. This wins but isn't saved.
2. `localStorage["tb.lang"]`, written by the VI | EN switch in the top-right corner of the play overlay.
3. Otherwise `vi`.

Switching applies at once, without a reload. `setLanguage` saves the choice. If the URL has `?lang=`, it rewrites that too, since the URL would win on the next reload. It sets `<html lang>` and then notifies listeners.

## Adding a string

1. Add the key to **`vi.ts`** in the right section, e.g. `"hud.lowAmmo": "SẮP HẾT ĐẠN"`. Keys are flat and dotted: `area.thing`.
2. Add the same key to **`en.ts`**. Typecheck fails until you do.
3. Use it:
   - **Static label** (built once, never changes while playing): `elT("span", "tb-foo__label", "hud.lowAmmo", parent)` from `ui/dom.ts`. It re-translates itself on a language switch.
   - **Dynamic text** (written when a value changes): `setText(node, t("zone.outside", { m, dps }))`. Cache what you showed, as HUD components already do. Subscribe with `onLanguageChange` and clear that cache, so the next update rewrites the text. Unsubscribe in `dispose()`.
   - **Text with styled parts** (a highlighted name inside a sentence): put the pieces in a template, `"{you} đã hạ gục {victim} bằng {weapon}"`, and call `renderTemplate(parent, t(key), { you: span, victim: span, weapon: textNode })`. Word order can differ between languages; the nodes are reused. See `ui/KillFeed.ts`.
   - **Labels passed as plain strings** (match setup options, screen buttons): the owner builds them with `t()` and rebuilds after `onLanguageChange`. See `OfflineMatch.showSetup`.

### Params and plurals

- `{name}` placeholders take `t(key, { name })`. A missing param stays visible as `{name}`.
- A plural message is an object: `{ one: "{count} KILL", other: "{count} KILLS" }`, chosen by `params.count`. Vietnamese has no plural forms, so `vi.ts` uses plain strings.
- A unit test checks that both catalogs use the same placeholders for every key.

### Hot paths

`t(key)` without params returns the catalog string and allocates nothing, so a per-frame fixed label is fine. With params it builds a new string, so only call it when the shown value changed. Item names are cached per language in `ui/equipment/labels.ts` (`itemName`, `itemNameUpper`).

### Writing Vietnamese

- Write natural gaming Vietnamese, the way Vietnamese PUBG players talk. Keep loanwords players really use: Knock, Headshot, Boost, Frag, Bo (the blue zone), Map, Seed.
- Don't translate weapon code names (AR-4, S-12, K-98, P-9) or calibers.
- Always use full diacritics. The HUD font is Roboto Condensed from Google Fonts (see `apps/client/index.html`), which has Vietnamese glyphs. The css2 API serves its `vietnamese` unicode-range subset automatically.
- Keep HUD strings short. Many HUD labels are `text-transform: uppercase` and `white-space: nowrap`. Check the zone timer (`.tb-mhud__zone`, 300 px), the weapon strip (`.tb-slot`), the death and result titles, and the interaction prompt in the browser.

## What is not translated

- DEV panels and logs stay in English: F3 stats, F4 perf, F6 net panel numbers, bot debug labels, `console.*`, and the `Hud.debugPreview` scripted views.
- Data from other modules: bot names, POI names on the map, and credit lines ("Title by Author (License) — URL", built in `game/Game.ts` and `audio/audioCredits.ts`).
- Shared gameplay code in `packages/**` stays language-free. The client has its own translated copies of text helpers, such as `killFeedText` (vs shared `killFeedLine`) and `killCauseLabel` (vs `killCauseName`).

## Adding a language

1. Add the code to `Language` and `LANGUAGES` in `language.ts`, and update `isLanguage`.
2. Create `xx.ts` as `export const xx: Messages = { … }`. Copy `en.ts` and translate it.
3. Register it in `CATALOGS` in `core.ts`.
4. Add `common.languageName.xx` to every catalog, and the short label to `LANGUAGE_SHORT` in `ui/PlayOverlay.ts`.
5. If the script needs glyphs Roboto Condensed lacks, add a font to `index.html` and to `--tb-font` in `ui/hud.css`.

## Tests

`apps/client/test/i18n/i18n.test.ts` checks:

- Key parity and placeholder parity between the catalogs.
- Interpolation and plurals.
- Vietnamese is the default, and `?lang=` overrides the stored choice.
- A grep guard: no English literal may be written to the DOM in `src/ui` (`textContent =`, `.data =`, `.title =`, `el(…, "text")`, `setText(…, "text")`, `.append("text")`). If a literal really must stay (a brand name), add it to `ALLOWED_LITERALS`. DEV-only files go in `SKIPPED_PATHS`.
